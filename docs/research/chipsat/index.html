ChipSat Flight Software in progress

Flight Software Engineer · Cornell SSDS · Fall 2026

Flight software for a chipsat — a gram-scale, single-board spacecraft — as its board moves from Arduino to STM32 ahead of rocket-launch testing.

Overview

I started this semester as a flight software engineer on the chipsat in Cornell’s Space Systems Design Studio. The board is migrating from Arduino to STM32. The first half of the semester reproduces the existing Arduino build so its behavior is pinned down and any latent bugs surface against a known-good reference; the second half ports the stack onto STM32. Two rocket launches are planned this semester so the software is exercised in real flight rather than only on the bench.

The work has just begun; this page describes the plan, not results.

Design decisions 03

  • Reproduce the existing Arduino build before porting anything, rather than rewriting straight onto STM32 — without a known-good reference there is no way to tell a port bug from a bug the firmware always had.
  • Move to STM32 because the chipsat’s size, weight, and power envelope rules the Arduino hardware out; the platform choice follows the SWaP budget, not developer convenience, and the MCU in turn bounds what the flight software can afford to do.
  • Plan flight testing on two rocket launches instead of bench testing alone, so the software meets the vibration, power, and timing conditions it actually has to survive.
